# Cursor Context - HelpDesk Task Management API

## Purpose
Standalone .NET 10 Task Management API with Clean Architecture, JWT auth, role-based access control, and PostgreSQL persistence.

## Architecture
- `HelpDesk.Domain`: entities, enums, repository contracts.
- `HelpDesk.Application`: use-case services (`TaskService`, `AuthService`), DTOs, validation, authorization rules.
- `HelpDesk.Infrastructure`: Npgsql repositories, JWT token generator, bcrypt password hashing, clock abstraction.
- `HelpDesk.API`: controllers, middleware, auth configuration, DI composition.

Dependency direction: `API -> Infrastructure -> Application -> Domain`.

## Key Rules
- All task endpoints require JWT auth.
- `Admin` can access all tasks; non-admin users only their own tasks.
- Only `Admin` can create tasks on behalf of other users.
- Only `Admin` can reassign task ownership.
- Only task owner can change task status.
- Soft-delete is implemented via `deleted_dt`.

## Authentication
- User model includes: `email`, `name`, `password_hash`, `role`.
- Passwords are hashed with bcrypt, never stored in plain text.
- JWT claims include `sub`, `email`, `role`.
- Auth endpoints: register, login, change-password.

## Data + Dev Runtime
- SQL schema and indexes live in `db/init.sql`.
- `docker-compose.yml` runs `db` and `api`.
- `docker-compose.dev.yml` enables API hot reload with `dotnet watch run`.

## High-Value Files
- `HelpDesk.API/Program.cs`: pipeline + JWT auth config.
- `HelpDesk.API/Middleware/AppExceptionMiddleware.cs`: application exception mapping.
- `HelpDesk.Application/Tasks/TaskService.cs`: core task authorization/validation.
- `HelpDesk.Application/Auth/AuthService.cs`: login/registration/password flow.
- `HelpDesk.Infrastructure/Repositories/*.cs`: SQL persistence implementation.
